title: "Webhooks"
description: "Recibe notificaciones cuando ocurren eventos en PrimeERP y verifica que vienen de nosotros"
---

Los webhooks envían una solicitud HTTP `POST` a una URL de tu elección cada vez que ocurre un evento en PrimeERP (por ejemplo, la creación de un producto de compra), para que no tengas que consultar la API periódicamente.

# Cómo crear una suscripción

1. En la aplicación de PrimeNet, ve a **Configuración → Webhooks** y presiona **+** para crear una suscripción.
2. Indica un **nombre**, la **URL** que recibirá las notificaciones (una dirección **HTTPS pública**) y activa uno o más **eventos** del catálogo.
3. Al guardar, PrimeERP muestra el **secreto** (`whsec_...`) con el que se firman las notificaciones. Cópialo: se muestra **una sola vez**. Si lo pierdes, rótalo.

<Warning>
  Trata el secreto como cualquier otra credencial: quien lo tenga puede falsificar notificaciones hacia tu endpoint.
</Warning>

# Catálogo de eventos

Cada evento tiene su propia página con el detalle de los campos que trae en `data`.

| Evento | Descripción |
| --- | --- |
| [`purchase_product.created`](/documentation/eventos/producto-compra-creado) | Se creó un nuevo producto de compra. |
| [`ecf.processed`](/documentation/eventos/ecf-procesado) | Un e-CF recibió su respuesta final de la DGII (aceptado, aceptado condicional o rechazado) o no pudo procesarse. |

# Formato de la notificación

Cada notificación es un `POST` con cuerpo `application/json` y estos headers, según [Standard Webhooks](https://github.com/standard-webhooks/standard-webhooks):

| Header | Descripción |
| --- | --- |
| `webhook-id` | Identificador de la **entrega**; es el mismo en todos los reintentos. Úsalo como clave de idempotencia. |
| `webhook-timestamp` | Marca de tiempo Unix (segundos) del intento. |
| `webhook-signature` | Una o más firmas, separadas por espacio (ver abajo). |

### Cuerpo de la notificación

```json
{
  "type": "purchase_product.created",
  "timestamp": "2026-08-02T16:35:00Z",
  "tenantId": "55dea78f-bbe3-4b04-97e3-26b33547bcf8",
  "data": {
    "id": 4821,
    "name": "Resina epóxica 5L",
    "categoryId": 12,
    "manufacturerId": 7,
    "brandId": 3,
    "packagingId": 2,
    "goodServiceApplicability": "Product",
    "isActive": true
  }
}
```

| Campo | Descripción |
| --- | --- |
| `type` | El evento (ver catálogo). |
| `timestamp` | Fecha ISO 8601 (UTC) en que ocurrió el evento; no cambia entre reintentos. |
| `tenantId` | La compañía donde ocurrió el evento. |
| `data` | Los datos del evento. Sus campos se documentan en la página de cada evento (ver catálogo). |

# Verificación de la firma

Cada notificación se firma con **HMAC-SHA256** usando el secreto de la suscripción. Verifica la firma antes de procesar el cuerpo:

<Steps>
  <Step title="Lee el cuerpo crudo y los headers">
    Necesitas el cuerpo sin parsear y los headers `webhook-id`, `webhook-timestamp` y `webhook-signature`.
  </Step>
  <Step title="Deriva la clave HMAC a partir del secreto">
    Quita el prefijo `whsec_` y decodifica el resto como **base64 URL-safe**; esos bytes son la clave.
  </Step>
  <Step title="Recalcula la firma">
    Calcula `HMAC-SHA256(clave, "{webhook-id}.{webhook-timestamp}.{cuerpo}")` sobre los bytes exactos recibidos (si re-serializas el JSON, la firma no coincidirá). Codifica el resultado en **base64** y antepón `v1,`.
  </Step>
  <Step title="Compara contra cada firma del header">
    Durante una rotación, `webhook-signature` trae dos firmas (`v1,firmaA v1,firmaB`). La notificación es válida si coincide **cualquiera**. Compara en tiempo constante, no con `==`.
  </Step>
  <Step title="Verifica que el timestamp sea reciente">
    Rechaza notificaciones con `webhook-timestamp` de más de 5 minutos, para evitar que se reenvíen (*replay*).
  </Step>
</Steps>

<CodeGroup>

```javascript Node.js
const crypto = require("crypto");

function decodeSecret(secret) {
  const encoded = secret.startsWith("whsec_") ? secret.slice(6) : secret;
  return Buffer.from(encoded.replace(/-/g, "+").replace(/_/g, "/"), "base64");
}

function isValidSignature(rawBody, idHeader, timestampHeader, signatureHeader, secret) {
  const timestamp = parseInt(timestampHeader, 10);

  // Paso 5: rechaza notificaciones con más de 5 minutos de antigüedad.
  const ageInSeconds = Math.floor(Date.now() / 1000) - timestamp;
  if (Math.abs(ageInSeconds) > 300) return false;

  // Paso 3: recalcula la firma sobre "{id}.{timestamp}.{rawBody}".
  const signedContent = `${idHeader}.${timestamp}.${rawBody}`;
  const expectedSignature = crypto
    .createHmac("sha256", decodeSecret(secret))
    .update(signedContent)
    .digest("base64");
  const expected = `v1,${expectedSignature}`;

  // Paso 4: puede haber varias firmas separadas por espacio; basta con que coincida una.
  const received = signatureHeader.split(" ");
  const expectedBuf = Buffer.from(expected, "utf8");

  return received.some((sig) => {
    const receivedBuf = Buffer.from(sig, "utf8");
    return (
      expectedBuf.length === receivedBuf.length &&
      crypto.timingSafeEqual(expectedBuf, receivedBuf)
    );
  });
}
```

```python Python
import base64
import hashlib
import hmac
import time


def decode_secret(secret: str) -> bytes:
    encoded = secret[len("whsec_"):] if secret.startswith("whsec_") else secret
    padded = encoded + "=" * (-len(encoded) % 4)
    return base64.urlsafe_b64decode(padded)


def is_valid_signature(
    raw_body: bytes, id_header: str, timestamp_header: str, signature_header: str, secret: str
) -> bool:
    timestamp = int(timestamp_header)

    # Paso 5: rechaza notificaciones con más de 5 minutos de antigüedad.
    if abs(int(time.time()) - timestamp) > 300:
        return False

    # Paso 3: recalcula la firma sobre "{id}.{timestamp}.{rawBody}".
    signed_content = f"{id_header}.{timestamp}.".encode("utf-8") + raw_body
    expected_signature = base64.b64encode(
        hmac.new(decode_secret(secret), signed_content, hashlib.sha256).digest()
    ).decode("utf-8")
    expected = f"v1,{expected_signature}"

    # Paso 4: puede haber varias firmas separadas por espacio; basta con que coincida una.
    return any(hmac.compare_digest(expected, sig) for sig in signature_header.split(" "))
```

# Rotación del secreto

Abre la suscripción y presiona **Rotar secret**. El secreto nuevo se muestra **una sola vez**. Durante **24 horas** las notificaciones se firman con el anterior y el nuevo, para que actualices tu verificación sin perder entregas.

# Reintentos

Cualquier respuesta distinta de `2xx` (incluidos timeouts y errores de conexión) se reintenta:

- El primer reintento es a **1 minuto** y la espera se duplica en cada intento, hasta **6 horas**. Si respondes con `Retry-After`, se respeta.
- Tras **3 días** desde el primer intento, la entrega queda como fallida.

<Warning>
  Si tu endpoint responde `410 Gone`, PrimeERP interpreta que ya no quieres recibir notificaciones y **desactiva la suscripción**. Para reactivarla, ábrela y marca **Activo**.
</Warning>

<Note>
  Si respondes `429`, `502` o `504`, se pausan **todas** las entregas pendientes de la suscripción hasta el próximo reintento.
</Note>

# Historial de entregas

Al abrir una suscripción verás sus entregas: estado (**Pendiente**, **Entregado** o **Fallido**), intentos, último código HTTP recibido y próximo reintento.

# Buenas prácticas

- **Responde `2xx` de inmediato** y procesa en segundo plano; una respuesta lenta cuenta como fallo y se reintenta.
- **Sé idempotente.** Puedes recibir la misma notificación más de una vez; descarta las repetidas por `webhook-id`.
