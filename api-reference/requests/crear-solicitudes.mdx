---
title: "Crear"
api: "POST /requests"
---

Crea una nueva solicitud (request) en la empresa, a partir de una plantilla previamente configurada.

<Note>
  Este endpoint requiere el scope **`Requests.Write`**.
</Note>

### Headers

<ParamField header="X-Tenant-Id" type="string" required>
  Identificador del tenant al cual pertenece el API Key.
</ParamField>

### Body parameters

<ParamField body="templateId" type="integer" required>
  Identificador de la plantilla de solicitud a utilizar. Determina el menú de origen y de destino de la solicitud.
</ParamField>

<ParamField body="originOperationId" type="integer">
  Identificador de la operación de origen (ej. el `id` de la factura por pagar). Debe existir en el menú de origen de la plantilla. Es equivalente a enviar `originOperationIds` con un único elemento.

  Se debe enviar `originOperationId` **o** `originOperationIds`, pero no ambos.
</ParamField>

<ParamField body="originOperationIds" type="integer[]">
  Lista de identificadores de operaciones de origen, para solicitudes con múltiples orígenes. Solo los siguientes menús de origen soportan más de un origen:

  - `CostEstimates` (estimados de costos): todos los estimados deben existir, estar activos, no estar ya facturados, no tener otra solicitud activa asociada, y compartir el mismo proveedor y la misma moneda.
  - `PurchaseRequisitionQuotes` (líneas de cotización de requisiciones de compra): ver [Aprobación de requisiciones de compra](#aprobación-de-requisiciones-de-compra).

  No se permiten IDs repetidos.
</ParamField>

<ParamField body="subject" type="string" required>
  Asunto de la solicitud. Máximo 100 caracteres.
</ParamField>

<ParamField body="description" type="string">
  Descripción de la solicitud. Máximo 250 caracteres.
</ParamField>

### Example request

<CodeGroup>

```bash curl
curl --request POST \
  --url "https://api.primenetcloud.com/v1/requests" \
  --header "X-Api-Key: YOUR_API_KEY" \
  --header "X-Tenant-Id: TENANT_ID" \
  --header "Content-Type: application/json" \
  --data '{
    "templateId": 4,
    "originOperationId": 8410,
    "subject": "Reembolso de factura DGV-002145",
    "description": "Solicitud de vale de caja chica por gastos de combustible"
  }'
```

import requests

response = requests.post(

### Ejemplo con múltiples orígenes

Con el menú de estimados de costos (`CostEstimates`), la solicitud resultante se resuelve como un único pago al proveedor, por lo que todas las cotizaciones enviadas deben compartir el mismo proveedor y la misma moneda.

```json
{
  "templateId": 4,
  "originOperationIds": [8410, 8411],
  "subject": "Pago combinado de cotizaciones",
  "description": "Pago de cotizaciones de flete y almacenaje del mismo proveedor"
}
```

### Aprobación de requisiciones de compra

Las [requisiciones de compra](/api-reference/purchase-requisitions/listar-requisiciones) y las líneas de sus cotizaciones se envían a aprobación creando una solicitud con una plantilla cuyo menú de origen sea el correspondiente:

- **Requisición** (`PurchaseRequisitions`): se envía con `originOperationId` igual al `id` de la requisición. La requisición debe estar en estatus `New` y tener al menos una línea, y la plantilla no puede tener autorización por rangos (`Range`), ya que la requisición aún no tiene montos. Al crearse la solicitud, la requisición pasa a `InApproval` (o directamente a `Approved` si la plantilla no requiere autorización). Si la solicitud es rechazada o eliminada, la requisición vuelve a `New` para poder corregirse y enviarse de nuevo.
- **Líneas de cotización** (`PurchaseRequisitionQuotes`): se envían con `originOperationIds` igual a los `id` de las líneas de cotización elegidas (o `originOperationId` para una sola línea). La plantilla debe requerir autorización; todas las líneas deben pertenecer a cotizaciones no canceladas de una misma requisición en estatus `Approved`, tener aprobación `NotSent` o `Rejected`, y cada línea de la requisición solo puede enviarse desde una cotización (y no debe estar ya en aprobación o aprobada en otra). Con autorización por rangos, el monto de la solicitud es la suma del total de las líneas, convertido a la moneda de la plantilla cuando las cotizaciones están en monedas distintas. Al crearse, las líneas pasan a aprobación `Pending`; al aprobarse o rechazarse la solicitud pasan a `Approved`/`Rejected` (los aprobadores pueden rechazar líneas individuales mientras aprueban el resto), y si la solicitud se elimina vuelven a `NotSent`.

```json
{
  "templateId": 9,
  "originOperationIds": [5012, 5013, 5020],
  "subject": "Aprobación de cotización - Requisición 37",
  "description": "Repuestos para mantenimiento preventivo de la flotilla"
}
```

<Note>
  Si la plantilla tiene como autorizador al supervisor (`authParticipant.type` igual a `Supervisor`), la solicitud solo puede ser enviada por un usuario que tenga supervisor asignado; un API Key no puede crearla.
</Note>

### Errores

<ResponseField name="400 Bad Request">
  El `templateId` no es válido, alguna operación de origen no existe en el menú de origen de la plantilla, el menú de origen no soporta múltiples orígenes, las cotizaciones de costo enviadas no comparten proveedor o moneda, alguna cotización ya está facturada o ya tiene una solicitud activa asociada, la requisición o las líneas de cotización no cumplen las condiciones para enviarse a aprobación, la plantilla tiene como autorizador al supervisor y la solicitud la envía un API Key (o un usuario sin supervisor), o la combinación de menú de origen/destino de la plantilla no está permitida.
</ResponseField>

<ResponseField name="403 Forbidden">
  El API Key no tiene el scope `Requests.Write` requerido.
</ResponseField>
